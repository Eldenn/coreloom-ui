# AI Agent Builder

Design an agent graph the way LangGraph models it, on the node editor: a shared **state**, **nodes** — Agent (a model with instructions and tools), Tools (runs the tools an agent asked for), Function (a step of your own code), Router (picks the next step: one output per route), Human review (pauses until a person answers), Subgraph — and **edges** between START and END. A Router is how the editor draws LangGraph's conditional edges. Nothing runs here: your app runs the graph (with LangGraph or anything else) and reports through `runs`.

**The consumer provides** `models` (the Agent node's picker; a text field without them) and `tools` (`{ id, name, description?, sensitive?, parameters? }`, offered to Agent and Tools nodes; `parameters` is the tool's input as a JSON Schema object), the graph (`value` / `onValueChange` or `defaultValue`, START and END by default), the state (`state` / `onStateChange` or `defaultState`, `messages` with append by default), the graph's settings (`config` / `onConfigChange` or `defaultConfig`: `{ recursionLimit? }`) and the name. Optionally: `onSave({ workflow, json, config, name })`, `onRun({ workflow, json, config })` — both get the graph, its LangGraph JSON and what `compile()` / `invoke()` take — `running`, `runs`, `onRunNode` ("Test node" on one node, as in the node editor), `interrupt` and `onResume` (below), `readOnly`, `defaultSelectedId` and `height`. The state's fields are offered in every node's `{{ }}` expressions.

- **State** opens the state's fields: a name, a type, and how an update applies — _Replace_ keeps the last value, _Append_ adds to a list (LangGraph's `add_messages` / `operator.add` reducers).
- **LangGraph JSON** shows the graph in the shape of `graph.get_graph().to_json()` and imports one. A Router becomes conditional edges from the nodes that lead to it, the route name in each edge's `data`. Positions, names and settings travel in each node's `metadata.coreloom`, so an export imports back unchanged.
- Importing a graph exported by LangGraph itself: each node with conditional edges gets a Router after it, `ToolNode`s become Tools, nodes named like an agent become Agents, the rest Functions; the graph is laid out left to right. Unknown or malformed entries are skipped.
- `toLangGraphJSON(workflow, state, config)` and `fromLangGraphJSON(jsonOrText)` (which gives `{ workflow, state, config }`) do the same in your code; `useAgentBuilderKinds({ models, tools, state })` gives the node kinds, to use `NodeEditor` directly (the sensitive-tool default is AgentBuilder's).
- `agentTeamToWorkflow(team)` and `workflowToAgentTeam(workflow, { tools })` convert between this graph and the agent teams block (ai-agent-teams): a delegation is a supervisor with a Router to its workers, who come back when done; a handoff is a route to the next agent.
- An Agent's instructions list the `{{variables}}` they use, read from the state.
- **Reads / Writes** on each node (Router: reads; Human review: where the answer goes) name the state fields it uses and updates; the card shows what it writes (`→ sources`). Only shown when the state has fields.
- **Structured output** on an Agent is a JSON Schema: the agent answers in that shape instead of free text (LangGraph's `response_format`). It must parse; the card says _Structured_.
- **Tool parameters**: for each picked tool with `parameters`, each parameter can be fixed — a value, an `{{ }}` expression or, for an `enum`, one of its values — or left empty for the model to choose. Stored as `toolArgs: { [toolId]: { [param]: value } }`.
- **Ask before running** lists the picked tools whose calls a person approves, edits or rejects first (`askFirst`, LangChain's human-in-the-loop `interrupt_on`). A tool marked `sensitive` is added when it's picked.
- **Limits**: an Agent's _Max steps_ (`maxSteps`, model and tool turns), _Max tokens per answer_ (`maxTokens`) and _Timeout_ (`timeout`, seconds); the graph's _Recursion limit_ under State (LangGraph's `recursion_limit`, 25 when empty).
- **Pause the run** (`pause: 'before' | 'after'`) on Agent, Tools, Function and Subgraph nodes: `toLangGraphConfig(workflow, config)` turns them into `interrupt_before` / `interrupt_after` (disabled nodes left out) with `recursion_limit`; the card says _Pauses_.
- **Review**: when your run pauses, pass `interrupt` — `{ nodeId, question?, actions?: [{ name, args, description?, decisions? }], decisions? }` — and a dialog opens: each tool call with its arguments and _Approve_, _Edit_ (the arguments as a JSON object, checked) or _Reject_ (with an optional reason); without actions, the question with _Approve_, _Reject_ and an answer (a Human review node's `interrupt()`; its `decisions` setting says which the reviewer gets). `onResume({ nodeId, decisions })` gets one decision per call in LangChain's shape (`{ type: 'approve' }`, `{ type: 'edit', edited_action: { name, args } }`, `{ type: 'reject', message? }`, `{ type: 'respond', message }`): resume with `Command(resume={ decisions })` and clear `interrupt`. _Later_ closes it; the _Review_ button opens it again.
- All these settings live in the node's `data` and travel in the LangGraph JSON's `metadata.coreloom`, the recursion limit in START's.

**In an app:** `pnpm dlx shadcn@latest add @coreloom/ai-agent-builder`.
